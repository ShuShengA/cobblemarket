# 培育屋（代练托管）计划

> 2026-08-25 起草，**下个版本实现**（当前 1.0.0 不包含）。
> 需求来源：与 AI 的方案讨论（桌面 培育屋.txt）经评估修正后的定稿。
> 核心结论：时间戳结算 + 套餐自选 + 随存随取按秒计费；精灵必须收走（原方案的 NBT 标记有白嫖漏洞）。

## 一、功能概述

玩家把宝可梦存入培育屋，选择速度套餐后按现实时间（秒）自动积累经验；取出时按总时长 × 每秒单价扣费。随存随取、按秒计费、无最低消费。满级自动停止计费（超挂的时间不收费）。

## 二、核心机制（已定）

1. **时间戳结算**：存入时记 `startTime`；取出时 `(now - startTime) / 1000 × 套餐速率` 一次性加经验、一次性扣费。全程无定时器（防卡服）。
2. **套餐自选**：服主在配置定义 tiers（id / xpPerSecond / costPerSecond），玩家存入时自选。成长速度与套餐完全解耦——快慢精灵用同一套套餐。
3. **满级停止**：结算时反推「到达 100 级的时间点」，经验与费用只算到该点；剩余时间不计费、不给经验。
4. **精灵收走**：存入时精灵从玩家手中取走、存服务端（复用挂单冻结模式），取出时归还。**托管期间精灵不可战斗/繁殖/交易**——原 AI 方案把标记写精灵 NBT、精灵不离手，玩家可一边挂机一边用精灵战斗白嫖经验，已否。
5. **离线照常**：玩家下线、服务器重启，时间照算（时间戳天然支持，无服务器在线依赖）。
6. **进化**：Cobblemon 精灵不会自动进化（需玩家在队伍里手动点进化按钮），托管升级到进化等级会停在未进化状态，无需处理。
7. **学招式**：⚠ 待查证 Cobblemon `addExperience` 的副作用（升级是否自动学招式）——若自动学则接受（与原版一致），不额外拦截。

## 四、配置设计

`config/cobblemarket/daycare.json`（首次启动生成默认，`/cobblemarket reload` 或对应命令热加载）：

```json
{
  "tiers": [
    { "id": "economy",  "xpPerSecond": 0.5,  "costPerSecond": 0.03 },
    { "id": "standard", "xpPerSecond": 1.17, "costPerSecond": 0.08 },
    { "id": "premium",  "xpPerSecond": 3.0,  "costPerSecond": 0.25 }
  ],
  "maxPokemonPerPlayer": 3
}
```

- 套餐名称走 lang 文件（`cobblemarket.daycare.tier.economy` 等），**不写在 json**（符合项目 i18n 惯例）
- 数值仅供参考（约 10 天满级基准），服主自行平衡
- 默认货币不进本配置——跟随全局货币配置

## 五、数据存储

- 服务端结构（照挂单模式，随持久化节流保存）：`ownerUUID / pokemon(序列化) / tierId / startTime`
- 与拍卖/求购单挂单同一套持久化与异常关服保障（交易后 saveAll 教训见既有实现）
- 无新增 NBT 需求（精灵收走后托管数据在服务端存储里）

## 九、已否掉的方案（记录防返工）

| 方案 | 否掉原因 |
|---|---|
| 步数挂机 | 水流跑道/脚本可刷步数 |
| 活跃在线时长 | 挂机判定复杂、可绕 |
| 消耗品燃料制 | 偏离「挂机托管」体验 |
| 最低消费（不足 1 小时按 1 小时） | 按秒计费后无意义，反而留漏洞 |
| 中途换套餐逻辑 | 取出重存即可，无需代码 |
| 精灵 NBT 标记托管状态 | 精灵不离手可白嫖（见二.4） |
| 超时管理费（maxStorageDays） | 默认不做，必要时再议 |
