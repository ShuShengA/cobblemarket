# 宝可梦金融系统计划（信用借贷 + 喵喵支付）

> 状态：已拍板（2026-08-28 定稿，2026-08-31 补存储与界面布局细节），1.1.0 主线
> 定位：给市场交易提供**信用支付能力**——玩家可以借未来的钱现在消费，为服务器注入资金流动性；同时是服主的运营杠杆（利率/额度/逾期制裁全可配）。

## 核心架构：准备金池资金闭环

- 准备金池（FinanceState 记账）是所有钱的唯一进出口
- 借款/信用支付 → 钱从池子出（直接给卖家/玩家钱包）；还款本金回池；利息 100% 进池；坏账从池冲销
- 准备金**允许为负**（= 服主负债，OP 面板红色告警）；服主不必预充
- 信用钱包本质 =「准备金垫付给卖家，玩家分期还回池子」，消费贷/现金贷统一模型
- 坏账冲销时池子不足 → 不销账、挂账告警 OP（经济安全优先，绝不凭空销账）

## 双形态（借呗 / 花呗对照）

| 形态 | 入口 | 资金流 |
|---|---|---|
| 现金贷（借呗） | 喵喵银行柜台主动借款 | 钱进玩家钱包，玩家分期还 |
| 消费贷（花呗 = 喵喵支付） | 购买精灵/物品弹窗的「喵喵支付」按钮 | 准备金直接垫付给卖家，玩家欠款分期还 |

- **拍卖出价入口已砍掉**（2026-09-05 拍板）：拍卖场景想借钱先走喵喵银行柜台现金贷再出价，功能闭环不受影响；`LoanSource.AUCTION_BID`、`LoanLogType.CONFIRMED` 死代码已清
- 每笔喵喵支付 = 一笔独立消费贷（统一模型，逐笔分期）
- 配置里有独立的现金贷开关与费率、消费贷开关，可各自启停

## 利息模型（统一按天）

- 日利率 = 每期费率 ÷ 7（每期 7 天；费率 0.5%/0.8%/1.2% 可配）
- 每期：本金 = 总额 ÷ 期数（等额本金）；利息 = 剩余本金 × 日利率 × 距上次还款天数
- 主动还款/自动划扣/提前结清同一条公式实算；UI 文案只说「每期费率」，**不写年化**（年化 25% 会吓退玩家且名义误导）
- 利息**不预存**：只在还款时从状态实算（LoanRecord 存 dailyRate 快照 + lastRepayAt 基准，改配置不影响存量贷款）

## 还款时点（2026-08-31 补拍板）

| 时点 | 行为 |
|---|---|
| 借款后、到期前 | 不扣款，玩家正常买卖 |
| **每期到期日**（借后第 7/14/21 天…） | **自动全额划扣**当期应还（本金+利息），划扣前保底 `autoRepayMinBalance`——最多划到余额=最低保留为止；划不足 → OVERDUE |
| 任意时刻 | 玩家可主动还款/提前结清（同一条公式实算） |

- 「划扣比例」参数已砍掉（全额划扣语义最干净，比例会造成「余额充足却只还一半→顺延乱账期/判逾期冤枉」两难）；想少扣就调高最低保留
- 金额一律 **Long**（与市场挂单/冻结金一致）；利息计算用 Double 实算后四舍五入

## 逾期状态机（复用现有系统）

- 到期未还 → OVERDUE（通知 + 禁止新增借贷）
- 逾期 7 天 → 市场手续费翻倍（挂现有 fee 计算）
- 逾期 14 天 → 冻结挂单/待领取（**复用 BanState**，新增封禁来源 FINANCE，拦交易不拦取回）
- 逾期 30 天 → BAD_DEBT：准备金冲销 + OP 报表记录

## 额度公式 + 防刷

- 额度 = 近30天交易额×0.5 + 历史交易额×0.1 − 当前欠款×0.3（min/max 钳制可配）
- **交易额只算买入方**（2026-09-01 拍板）：借贷对应「花钱的能力」，卖家成交额与还款能力无关
- **防刷核心：借贷来源的交易不计入交易额**（防借→买→额度涨→再借循环）
  - 喵喵支付（消费贷）成交：成交记录标 loanFunded，直接不计额
  - 现金贷：钱进钱包与自有资金混同无法精确追踪 → **有未结清贷款时，该玩家买入成交一律不计额**（保守，防刷优先，2026-09-01 拍板）
- 交易对检测（30 天内同一买卖对 ≥3 笔后该对后续成交不计额）、同 IP 降权 10%（买卖双方同 IP 时该笔 ×0.9，30 天窗口，OP 豁免）
- **同 IP 聚合欠款上限 `ipDebtLimit`**（2026-09-01 拍板，防「同 IP 多小号借款转给主账号」）：借款/喵喵支付时，30 天窗口内记录过该 IP 的所有玩家未结清欠款总和 + 本次金额 > 上限 → 拒绝；OP 豁免，0=不限制。交易对检测拦单号循环放大，此上限从 IP 维度封死号海攻击规模（NAT 误伤分析：正常玩家人均欠款低，撞线概率小，阈值可配）

### 借款校验链（2026-09-01 拍板）

- 借款准入：`financeEnabled` + `cashLoanEnabled` + 无 OVERDUE/BAD_DEBT 贷款
- 金额校验：`0 < amount ≤ creditLimitFor(uuid)`（额度公式已含欠款×0.3 负向项，无需再扣）
- IP 校验：`ipDebtLimit > 0` 且非 OP 时，`debtByIp(ip) + amount ≤ ipDebtLimit`（同 IP 聚合欠款上限）
- 方案校验：planIndex 有效，`dailyRate = feeRate ÷ 7` 创建时快照
- 借款入账：`CurrencyHandler.give` 进玩家钱包；物品货币模式背包满 → **未发放部分挂市场待领取余额**（`addPendingBalance`，钱不丢，2026-09-01 拍板）
- 还款扣款来源：玩家货币余额（`CurrencyHandler.remove`，金额钳制在 Int 范围内）；自动划扣保底 `autoRepayMinBalance`

## 防套利补丁（2026-09-05 拍板）

### 存贷利率护栏（防「借钱存银行」套利）

- 风险：存款日利率 > 贷款日成本时，「借款 → 存银行吃利息 → 还贷」无限循环刷钱；且分期摊还 + 自有资金还贷的组合下，套利上界不是简单的日利率相等，而是更紧的均摊系数
- 护栏：配置**加载与保存**时自动钳制 `dailyDepositRate`，上界 = `min(每期费率 × (期数+1) ÷ (14×期数))`（遍历全部贷款方案取最小值）；超出钳制 + `CobbleMarket.LOGGER.warn`
- 该上界覆盖全部还法：按期自动划扣 / 提前结清 / 自有资金还贷而贷款存满全程，任何路径利息差 ≤ 0
- 免息贷款（费率 0）→ 存款日利率同步钳 0
- 默认值校验：0.0001 < 3 期方案上界 0.005×4/42 ≈ 0.000476，余量 4.8 倍
- 调用点：`load()` 应用后、`save()` 前（端点双保险；2026-09-05 收敛——唯一 setter 调用路径 applyAll 与 save 同同步块原子执行，无中间态窗口；且 save 前按**最终方案**上界钳，若在 setter 内钳会因 applyAll「先设利率后设方案」的顺序用旧上界误钳「同时涨价方案+利率」的合法组合）
- 界面透明（2026-09-05 补）：保存后客户端对比「提交值 vs 回发快照值」，不一致在配置界面底部显示黄色钳制提示（免息清零/输入超限统一覆盖）

### 净存款门槛（防「借钱包装存款冲申请条件」）

- 风险：紫/黑卡申请条件含「存款余额」，玩家借 50 万存进银行 → 存款+50 万、欠款+50 万，名义存款满足门槛骗取卡片资格
- 修法：申请资格判定与条件快照改用**净存款 = 活期存款余额 − 未还欠款（不含坏账）**；`FinanceState` 加 `netDepositBalance(uuid, now)`，`isPurpleCardEligible` / `isBlackCardEligible` / `sendPurpleCardApplyInfo` / `sendBlackCardApplyInfo` 四处替换
- 界面透明：申请界面条件行显示净存款值，文案「存款余额要求」改「净存款要求」（zh/en 双份，配置界面与申请界面共用同 key）

## 全服累计成交额

- FinanceState 记账**全服**历史累计成交额（市场+拍卖+求购，成交时累加）
- **仅入口界面展示，给玩家看**（服务器经济规模氛围用途）；不参与任何金融计算（额度/准备金无关）

## 存储设计（2026-08-31 补拍板）

| 层 | 载体 | 内容 |
|---|---|---|
| 状态（重启不丢） | `cobblemarket_finance.dat`（PersistentState + .bak） | 贷款状态机、准备金、IP 记录、欠款汇总（PersistHelper 兜崩溃） |
| 审计（服主查账） | `config/cobblemarket/credit/` **独立目录** | `loan_records_<日期>_<语言>.csv` + `repayment_records_<日期>_<语言>.csv` |

- 审计 CSV 照 TransactionFileLogger 模式：中英双份 + README 说明 + CSV 注入防护 + 按天分文件，**只写不改**（只追加）
- **不混入交易账本**（`history/` 目录）：交易账本回答「货去哪了」，信用账本回答「钱怎么走的」，互不污染；history 的 README 三步对账指南保持纯粹
- loan_records 事件与来源列：
  - 创建：来源 = 柜台（现金贷）/ 购精灵 / 购物品（消费贷）
  - 撤销（服主撤销坏账）、逾期标记、坏账事件
- repayment_records：每笔还款（主动/自动划扣/提前结清，金额/利息拆分/方式）

## 配置（2026-08-31 补拍板，2026-09-01 修正为 GUI 可编辑）

```json
"finance": {
  "enabled": false,                // 总开关，默认关
  "cashLoanEnabled": true,         // 现金贷（借呗）
  "consumerLoanEnabled": true,     // 消费贷（喵喵支付）
  "loanPlans": [                   // 分期方案数组（期数+每期费率，每期 7 天）
    {"periods": 3, "feeRate": 0.005},
    {"periods": 6, "feeRate": 0.008},
    {"periods": 12, "feeRate": 0.012}
  ],
  "creditLimit": {"recent30Weight": 0.5, "historyWeight": 0.1, "debtWeight": 0.3, "min": 0, "max": 100000},
  "autoRepayMinBalance": 1000,     // 自动划扣最低保留（砍掉划扣比例，全额划+保底）
  "ipDebtLimit": 100000,           // 同 IP 未结清欠款总和上限（防小号；OP 豁免；0=不限制）
  "overdueDays": {"feeDouble": 7, "freeze": 14, "badDebt": 30}   // 三档可改
}
```

- **`enabled` 默认关闭**，服主显式开启才生效——借贷影响经济安全，不主动打开。关闭时禁止新增借贷与信用支付，**已有贷款状态机照常运行**——还款/逾期/坏账不受影响，与市场总开关「只拦新交易不卡资产」同哲学
- 全部 14 项**进 ServerConfigScreen**（金融区块：区块内行间无分割线连排，仅上下分割线对框住，2026-09-01 拍板；loanPlans 用逗号文本输入框照 auctionDurationOptions）——利息快照制（dailyRate 创建时快照）使热改安全：改配置只影响新贷款，存量贷款用创建时的快照。唯一不能热改的仍是货币（切换后端账本错乱）
