# 管理权限节点计划

> 状态：方案已定，**排期 1.1.2**，节点粒度待拍板（2026-09-10）
> 定位：把「仅 OP」的管理入口开放给服主指定的玩家 —— 服主不必给 OP，就能让某人只管黑名单、只管封禁、或只管价格限制。

## 核心决策：自建权限系统，不依赖外部

不引 `fabric-permissions-api`、不依赖 LuckPerms，权限授予表由模组自己存：

- **零依赖**，纯 common 实现，双平台自动同步（不碰 platform 层、不新增硬依赖声明）
- **服主零门槛**：不用先装权限插件、不用学第二套命令
- **与模组既有体系同构**：紫金卡/黑金卡本质就是「资格集合 + 物品凭证 + 命令授予 + 限量」，权限表是同一模式去掉物品外壳

### 判定结构

```
MarketPermissions.has(player, node)
  1. player.hasPermissionLevel(2)        ← OP 自动全有（零配置、向后兼容）
  2. || 自建授予表含 node                 ← 服主显式授予
  3. || 外部权限桥（预留，一期不做）        ← 给"想在 LuckPerms 里统一管"的服主留的扩展点
```

第 1 条保证现在所有 OP 行为与今天**完全一致**，什么都不用配。

## 节点粒度（**待拍板**，决定界面形态）

| 粒度 | 效果 | 代价 |
|---|---|---|
| 粗（`cobblemarket.admin`） | 只能全给或全不给 | 用处有限 |
| **中（按功能域，8-12 个）** | 满足「只让某人管黑名单」这类真实需求 | 推荐 |
| 细（每操作一个，约 59 个） | 最灵活 | 维护爆炸 |

推荐按功能域切：`.admin.blacklist` / `.pricelimit` / `.ban` / `.finance` / `.auction` / `.item` / `.config` …

**这个选择直接决定界面**：中粒度一屏平铺即可，不需要「分组展开/折叠」那一层；细粒度才需要分组，且要处理「展开列表遮住下层控件」的坑（见下文）。

## 服务端改造

- 全项目 **59 处** `hasPermissionLevel(2)`（18 个文件：服务端约 51 / 客户端 8）
- 现有模式一律是 **C2S 包首行** `if (!player.hasPermissionLevel(2)) return@registerC2S`，逐处换成 `MarketPermissions.has(player, NODE)`
- 客户端判定只控「按钮显不显示」，**安全判断永远只在服务端** —— 这条不能破

## 客户端改造（比预想小）

各管理界面（AdminBanScreen / PriceLimitScreen 等）**自身没有任何客户端权限判断**，入口靠「管理面板按钮仅 OP 可见」这唯一一道门。所以只需：

- 一份「我的权限节点」快照（照 `CreditInfoPayload` 的做法：登录时 + 变更时推送）
- `MarketEntryScreen` 入口按钮按快照显示
- `AdminScreen` 内各按钮按快照显示/隐藏
- 零星几处：`LoanHistoryScreen:309`（坏账撤销按钮）、`MeowthBankScreen`（管理行）

### 入口判定

```
hasPermissionLevel(2) || 拥有任一 admin.* 节点
```

注意是「任一**管理类**节点」而非「任一权限」—— 若将来存在非管理类节点（卡片映射、只读功能开关），后者会显示出一个点进去啥也干不了的面板。

**判定由服务端算好、随快照推给客户端**，客户端读布尔值，不自己拼节点集合（省事 + 防伪造）。

### 入口按钮的连带改动

- 该按钮将**去掉文字、只保留图标**（沿用既有去文字化方向），所以：
  - 文案 key `cobblemarket.entry.op` 改为中性命名（去文字后只留给 tooltip）
  - 注释「行 3：管理员面板居中（仅 OP）」→「有管理权限者可见」
  - `openIfMarketEnabled` 里的 `isOp` → `canManage`；参数 `opBypass` → `adminBypass`
- **tooltip 补位（必须）**：去文字后，刚被授权的玩家只看到一个不知名图标。现有 `TextureButton` 未接 tooltip 参数（只有 NineSliceButton 有），需确认支持或补上
- 关市放行逻辑（`opBypass`）同步从「OP 放行」改为「管理权限放行」
- 按钮宽度保持 87 居中，与上两行对齐

## 界面方案

### 主界面（照 `AdminBanScreen`）

- **搜索玩家名**：客户端 250ms 防抖 → 服务端联想（在线玩家 + playerdata + usercache.json）→ 下拉最多 8 行 → 点选填入、点空白收起、快照丢弃陈旧响应 —— 这套逻辑原样复用
- 「添加」按钮 → 打开配置弹窗（**不是**确认类弹窗）

### 配置弹窗（照 `PriceLimitScreen` 的编辑弹窗，**不是**封禁的确认弹窗）

- 归类差异：封禁那个是「确认执行」类（240×150，说明文字 + 确认/取消）；本需求是「可反复编辑 + 保存」的**配置类**，骨架照价格限制的 220×150 编辑弹窗
- **多选按钮**：`NineSliceButton.pressedVisual = true` 即红底选中态（纹理第三段），与「手持物品」按钮（BlacklistScreen / PriceLimitScreen / BuyOrderScreen）同一机制
- **保存语义**：弹窗内多选 → 点保存 → **一次发完整集合**，服务端算差集并写审计（不要每点一个按钮发一次包）
- 打开时照黄金模板：`drawScreenDimMask` 遮罩 + 隐藏下层控件 + 关闭时 `clearChildren()+init()` 重建

### 行（一行 = 一个玩家）

- 行中段显示该玩家的节点小标签；右侧「编辑」(44×16) + 「删除」(44×16) 两个显式按钮（照价格限制）
- 编辑走同一弹窗并预填；确认时服务端「先删旧再插新」（价格限制的既有做法）
- 数据变化/过滤/滚动时重建行按钮；弹窗期间行按钮 `visible=false`

### 界面元素位置与布局

**实施时定**（不在本文档范围）。

## 实现坑

1. **弹窗内若做展开/折叠列表**，被列表覆盖的控件必须 `visible=false` —— MC 点击遍历按控件添加顺序走，不隐藏会被先添加的控件拦截（价格限制有专门注释）。中粒度平铺即可绕开此坑
2. 弹窗一律走黄金模板（遮罩 + 隐藏下层 + 重建）
3. 权限判定一律放服务端 C2S 包首行

## 授予后同步

授予/收回后，若目标玩家在线，需推一条刷新让他界面上按钮即时出现/消失（照 `broadcastCardHolderBoard` 的广播模式）。

## 审计

权限变更（谁给谁加了/减了什么节点、时间、执行者）记入既有 CSV 审计体系。

## 命令（OP 用，与界面双入口）

```
/market perm grant <玩家> <节点>
/market perm revoke <玩家> <节点>
/market perm list [玩家]
```

## 明确不做（一期）

- **外部权限系统桥**（LuckPerms / fabric-permissions-api）：判定结构第 3 层预留位置，一期不接
- **显式拒绝**（给 OP 也禁某功能）：只有「授予/不授予」
- **组 / 继承 / 临时权限**：重复造轮子，不做
- **卡片 ↔ 节点自动映射**：卡片是经济系统里的身份，节点是服主授予的管理职责，底层保持两套独立（将来若做映射，是便利功能而非机制合并）

## 排期与分步

**排期：1.1.2**（2026-09-10 拍板）。

- **不并入 1.1.1**（图标动画批次）：那是纯客户端渲染，本计划是全栈基础设施（服务端判定 + 协议 + 存档 + 界面），混版会让测试矩阵与排查路径互相干扰
- **必须排在 1.2.0 管理功能（商会 / 黑市 / 市场天气 / 数据运营包）之前**：那四个都是管理端密集型，先做权限层它们就自带节点，晚做则每个功能改两遍
- 节点粒度建议在 **1.1.1 开发期间**定下来，1.1.2 一开局即可动手

- **S0：只收口，不引权限**。建 `MarketPermissions.has(player, node)` 门面，59 处裸 `hasPermissionLevel(2)` 全部改走它，**行为零变化**（内部仍查 OP 等级）。零协议改动、可回归验证；做完之后新功能不再写裸调用
- **S1：自建授予表 + 命令 + 界面 + 客户端快照**。存储用新建 PersistentState（与黑名单/封禁名单一致），**不放 config**（权限是运行期数据）

**触发条件：节点粒度拍板后开工**（S1 依赖粒度；S0 不依赖，随时可搭车）。S0 的成本不随功能增长而涨价（永远是机械替换），但「粒度」拖到功能堆完再定会返工。
