# 外部签名码 · 测试站

用来**在本地跑通**「网站卖 RP」这条链路，验证 `docs/points_external_code_zh.md` 里的协议描述
第三方照着能不能实现、游戏服务端认不认。

## 它验证什么

1. **协议可实现**：`selftest` 用文档「四、测试向量」的固定输入复现期望的码
   （与 `tools/SignPointCode.java` 的结果逐字符对齐 —— 跨语言独立实现能对上，说明协议无歧义）
2. **端到端能兑换**：网页签出的码，在游戏里能兑换到账

## 怎么用

### 0. 自检（不需要游戏，几秒）

```bash
node tools/website-test/server.js selftest
```

### 1. 起测试站

```bash
node tools/website-test/server.js 8080 你的密钥
```

密钥要与你游戏服务端配置里的**「外部签名码的 HMAC 密钥」完全相同**，否则签出来的码不认。
（也可以用环境变量：`CM_SECRET=你的密钥 node tools/website-test/server.js 8080`）

### 2. 拿一张码

浏览器打开 `http://localhost:8080` → 选个档位 → 点「我已支付」
（**这一步是模拟的**：不接任何支付渠道，点了就直接签发）→ 复制兑换码。

### 3. 进游戏兑换

RP 市场 → 兑换框粘贴 → 点「兑换」→ 余额应增加对应面额，兑换记录里多一条。

## 反例更值得测

| 测什么 | 怎么造 | 预期 |
|---|---|---|
| **密钥不匹配** | 换个密钥起站再签一个 | 游戏内兑换失败 |
| **已过期** | 把 `DEFAULT_VALID_DAYS` 改成 1 再签；或把服务端「外部码有效期上限」调成 0 天 | 兑换失败 |
| **重放** | 同一个码兑换两次 | 第二次失败（serial 只认一次） |
| **面额非法** | 直接改 `TIERS` 里的 amount 为 0 再签（`sign()` 会拒绝） | 签不出来 |

## 注意

⚠ 这是**测试站**，不是给服主直接用的成品 —— 真上线要自己接支付渠道、记账、防刷，
到账确认之后才签发（本测试站是「点一下就当成功」，所以直接签）。
⚠ 密钥只能待在服务端进程里，**绝不能写进页面** —— 进了前端等于把印钞机交出去。
